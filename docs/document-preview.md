# 서류 작성·미리보기

기존 ‘꾸러미(ZIP)’ 대신, 서류를 **한 장씩 열고 → 정보를 채우고 → 채워진 실제 파일을 화면에서 확인한 뒤 → 개별 저장·인쇄**하는 흐름입니다. ZIP을 풀거나 파일을 찾을 필요가 없습니다.

## 화면 흐름

1. **서류 고르기**: 서비스에 등록된 기관 서류 중 하나를 고르고 ‘이 서류 열기’를 누릅니다. 선택한 서류만 내려받습니다.
2. **내 정보로 채우기**: 이름·연락처·생년월일·주소를 입력합니다. 계좌, 대리 신청, 주민등록번호·소득은 필요한 서류에서만 펼쳐 입력합니다.
3. **작성한 서류 확인하기**: 채워진 파일을 화면 뷰어로 보여 줍니다(이전 쪽·다음 쪽·확대·인쇄). 조례 본문이 앞에 붙은 서류도 내 정보가 들어간 쪽을 먼저 엽니다. 채운 항목과 직접 확인할 칸을 함께 안내합니다.
4. **저장·인쇄**: ‘작성한 서류 저장하기’ 또는 뷰어의 인쇄 버튼을 사용합니다. 원본이 필요하면 원본도 따로 저장할 수 있습니다.

입력 정보를 고치면 이전 작성본은 즉시 사라지고, ‘입력한 내용으로 서류 채우기’를 다시 눌러야 새 작성본이 나옵니다(수정 전 파일이 남는 문제 방지).

## 양식 상태

| 상태 | 의미 | 화면 안내 |
|---|---|---|
| `verified` 검증된 양식 | 원본 파일 SHA-256, 현재 엔진 버전, 화면 검토 기록이 모두 일치 | 화면 검토를 거친 양식 |
| `new` 처음 보는 양식 | 등록 기록 없음. 신청서 영역 분석 후 채움 | 채워진 곳과 빈칸을 꼭 확인 |
| `changed` 바뀐 양식 | 파일명은 등록됐지만 내용(해시)이나 엔진 버전이 다름 | 양식이 바뀌어 한 번 더 확인 |
| `reference` / `manual` | 신청서 영역을 확인하지 못함 | 원본을 보여 주고 직접 작성 안내 |

검증 목록은 [`data/form_registry.json`](../data/form_registry.json)에 있습니다. 항목은 `checks.visual_review: true`와 `reviewed_at`이 있고 `engine_version`이 `document-workspace-1`일 때만 검증된 양식으로 인정합니다. 엔진을 바꾸면 버전을 올리고 다시 검토해야 합니다.

## 새 양식 분석 (`src/document_workspace.py`)

- **HWPX**: 신청서 제목(신청서·신고서·동의서·위임장 등) 바로 아래 표이면서 성명·주소·생년월일·연락처·계좌 항목이 2개 이상인 블록만 채웁니다. 공고문·운영지침 안에 들어 있는 신청서도 파일명과 관계없이 찾습니다.
- **PDF**: 같은 기준으로 신청서 쪽만 채우고, 조례 본문 쪽은 건너뜁니다. 입력칸형 PDF는 이미 값이 있는 칸을 덮어쓰지 않습니다.
- **HWP**: 안내문과 신청서가 섞인 바이너리 파일은 영역을 안전하게 구분하지 못하므로, 파일명이 단독 신청서일 때만 자동 작성합니다.
- **제외**: ‘은행에서 작성’, ‘담당 공무원 작성’, 작성 예시, 접수·관리대장 영역은 채우지 않습니다.

## 서류별 표기 맞춤 (`src/field_format.py`)

입력은 편한 대로 받고, 서류에 적을 때는 그 서류의 표기를 따릅니다.

- **생년월일**: `19500101`, `1950.1.1`, `1950-01-01`, `500101`, `1950년 1월 1일`을 모두 읽습니다. 신청서 부분에 `년  월  일` 자리가 있으면 `1950년 1월 1일`, `20 .  .  .`이면 `1950. 1. 1.`, 예시가 `1950-01-01`이면 그 모양으로 넣습니다. 근거가 없으면 공문서 표기 `1950. 1. 1.`을 씁니다.
- **전화번호**: 국번 규칙대로 하이픈을 넣습니다(010-1234-5678, 02-123-4567, 031-123-4567, 1588-1234, 0505-123-4567). 서식에 `(   )   -` 자리가 있으면 `(010) 1234-5678`, ‘숫자만’ 안내가 있으면 숫자만 씁니다.
- **칸별 안내**: `생년월일(YYYYMMDD)`, `연락처(숫자만)`, `생년월일(예: 1950-01-01)`처럼 칸 이름에 형식이 적혀 있으면 서류 전체 표기보다 그 칸 안내를 먼저 따릅니다.
- 표기는 신청서로 인정된 부분(HWPX 블록, PDF 쪽, HWP 구조)의 글자에서만 읽습니다. 조례 본문의 개정일 같은 날짜는 섞지 않습니다.
- 읽을 수 없는 값(자릿수가 맞지 않는 번호, 없는 날짜)은 바꾸지 않고 입력 그대로 둡니다. 입력란 아래에 확인 안내를 띄웁니다.
- 서류 표기로 넣었을 때 칸이 좁아 빠지는 항목이 생기면, 짧은 표기(`01012345678`, `1950.1.1.`)로 한 번 더 채워 보고 더 많이 채워진 쪽을 씁니다.

## 주소 확인 (`src/address_check.py`)

‘주소 확인하기’를 누르면 아래 순서로 확인하고, 사용자가 후보를 골라 ‘이 주소로 바꾸기’를 눌러야 바뀝니다.

1. 띄어쓰기 정리: `서울특별시강남구테헤란로123 101동202호` → `서울특별시 강남구 테헤란로 123, 101동 202호`. 숫자는 지우거나 만들지 않습니다. 제주시·광주시처럼 시·도와 헷갈리는 시 이름은 그대로 둡니다.
2. AI 검수(`LLM_API_KEY`): 띄어쓰기와 명백한 오타만 고칩니다. 입력에 없던 숫자(동·호·번지)가 생기면 결과를 버립니다.
3. 도로명주소 검색(`JUSO_API_KEY`, 행정안전부 도로명주소 검색 API): 실제 주소 후보를 보여 주고, 하나만 나오면 상세주소(동·호)를 붙여 제안합니다.

키가 없거나 호출이 실패하면 그 단계만 건너뛰고 안내 문구를 띄웁니다. 주소 한 줄만 보내고 이름·연락처·생년월일은 보내지 않습니다.

## 작성 후 검사

- 작성한 파일을 다시 열어 구조를 확인하고(HWP는 hwplib 재열기), 실패하면 원본을 보여 줍니다.
- 칸이 좁아 글자가 넘치면 억지로 작게 넣지 않고 빈칸으로 남겨 ‘직접 작성’으로 안내합니다.
- 8pt 미만 글씨는 확대 확인을 안내합니다. 입력칸형 PDF는 화면 확인·인쇄용이며 온라인 제출 입력값으로 전달되지 않는다고 안내합니다.

## 개인정보

입력 정보와 작성한 파일은 현재 Streamlit 세션에만 보관하고 DB·공유 캐시·외부 변환 서비스로 보내지 않습니다. 예외는 사용자가 ‘주소 확인하기’를 눌렀을 때 주소 한 줄을 AI 검수와 도로명주소 검색으로 보내는 경우뿐입니다. 결과 묶음(`prepare_document` 반환값)에는 표기 종류만 남기고 입력값은 넣지 않습니다. 화면 뷰어는 같은 페이지 안에서 렌더링합니다. ‘입력 정보와 작성한 서류 지우기’로 즉시 삭제할 수 있습니다.

## 검증 범위와 한계

- 자동 테스트: `python -m unittest discover -s tests` (227개 통과, 2026-11-20). 표기 맞춤·주소 확인·화면 흐름 테스트 포함, 외부 API는 가짜 응답으로 대체.
- 실제 양식 회귀: 복지로 첨부 22개(PDF·HWPX·HWP)에서 표기 맞춤을 켠 경우와 끈 경우의 채운 칸 수·상태·경고가 모두 같음(2026-11-20).
- 운영 DB 실데이터 회귀: 신청서 첨부 140개(무작위 2회, HWP·HWPX·PDF)를 복지로에서 내려받아 비교. 좁은 칸 재시도 반영 후 내려받기 실패 1건 외 모두 동일하거나 같은 칸 수(2026-11-20).
- 화면 확인: HWP·HWPX·PDF 뷰어 렌더링, 검증 양식 안내, 작성한 쪽 자동 이동, 데스크톱·모바일(390px) 폭, 정보 수정 시 이전 저장 버튼 제거를 Playwright로 확인.
- 검증 양식은 현재 1건(의성군 별지서식 PDF, 가상 정보 18칸)입니다. 모든 입력 길이, 실제 프린터, 기관 접수 승인을 보증하지 않습니다.
- 한컴오피스 GUI 열기·인쇄는 별도 확인이 필요합니다. 서명·날인은 직접 해야 합니다.

## 검증 양식 추가 방법

1. 가상 정보로 서류를 채운 뒤 바뀐 쪽을 렌더링해 글자 깨짐·넘침·잘못된 칸을 눈으로 확인합니다.
2. 원본 파일의 SHA-256, 파일명, 검토 날짜, 채운 쪽, 확인한 항목, 한계를 `data/form_registry.json`의 `entries`에 추가합니다.
3. `checks.visual_review`는 실제로 눈으로 확인한 경우에만 `true`로 둡니다.

## 칸 모양별 기입 규칙 (운영 DB 신청서 770개 분석으로 추가)

- **안내 글자가 인쇄된 값 칸**: `(남, 여)`·`(만 세)`·`(양, 음)`·`(현 거주지)`·`(전화번호 : )`는 값을 앞에, `☎`는 뒤에 넣고 안내 글자는 남깁니다. 서명·날인 칸은 건드리지 않습니다.
- **정부 표준서식(칸 위쪽에 라벨만 있는 칸)**: 오른쪽이 또 다른 라벨이거나 칸이 없으면 같은 칸 라벨 뒤에 이어 씁니다(예: `성명  홍길동`).
- **채우지 않는 칸**: 같은 열에 같은 라벨이 반복되는 명부, 줄 머리가 가족·가구원·세대원·자녀인 칸, `부`/`모`로 나뉜 칸, `신청아동`·`대상아동`·`입양아동` 같은 아이 칸. 아이 칸이 끝난 뒤 `주소`·`연락처` 줄은 다시 신청인 칸으로 봅니다.
- **PDF**: 오른쪽 칸에 `자택:`/`휴대전화:` 같은 작은 라벨이 있으면 아래 칸으로 내려가지 않고, 여러 줄 칸은 해당 줄 높이에 맞춰 씁니다. 글자 정보가 없는 스캔본은 ‘옮겨 적을 내용’과 발급 안내를 보여 줍니다. 40쪽이 넘는 PDF는 신청서 쪽만 미리 보여 줍니다.
- 여러 사람 칸 차단(전수 점검 후 추가): 한 쪽에 서명 줄이 3개 이상인 PDF 서명 명단, `연번`·`순번` 명단 표, 같은 구역 머리 안에서 두 번째로 나오는 성명·생년월일·주민번호(배우자·자녀·미망인 칸 등), `출생아`·`부모 외의 보호자` 칸.
- `대상자` 구역만 있고 서식 어디에도 신청인·신청자·청구인·보호자가 없으면 대상자 본인을 신청인으로 봅니다(요청마다 따로 정하는 contextvar).
- 기관 보안(파수 DRM)으로 암호화된 첨부는 열 수 없다고 정확히 알리고 받는 방법만 안내합니다. HWP 라이브러리가 다시 저장하지 못하는 3개 서식은 원본과 옮겨 적을 내용을 보여 줍니다.
- 결과(신청서 770개, 같은 가상 정보): 이름 1,013→1,037칸, 연락처 548→648칸, 주소 406→465칸, 생년월일 346→369칸. 다른 사람 칸·명단에 잘못 들어가던 기입(서명 명단 24칸 등)은 빠졌습니다.

## AI 도움 (`src/doc_assist_ai.py`, `src/chat_ai.py`, `LLM_API_KEY`)

- **신청서가 없거나 자동 작성이 안 될 때**: 온라인·방문·전화로 신청서를 받는 방법, 함께 낼 서류와 발급처(정부24·홈택스 등 바로가기), ‘AI에게 쉽게 설명 듣기’(공식 안내문만 보냄)를 보여 줍니다.
- **AI 상담**: ‘AI와 대화로 찾기’는 OpenAI와 자유롭게 대화하며 지역·나이·가족·필요한 도움을 모으고, 끝나면 후보 중 가장 맞는 3개를 골라 ‘먼저 볼 복지’로 보여 주고 신청서 채우기로 안내합니다. 키가 없거나 실패하면 정해진 질문 상담으로 돌아갑니다.
- **새 창에서 크게 보기**: 미리보기 도구 막대에서 모든 쪽을 새 탭에 크게 엽니다(PDF는 브라우저 PDF 화면).

## 서류와 참고 자료 구분 (`document_workspace.attachment_kind`)

- 첨부 이름에 신청서·서식·동의서·위임장·계획서·의뢰서 등이 있으면 **서류**, 사업안내·지침·공고·조례·매뉴얼·법률·계획·기준·별표 등만 있으면 **참고 자료**입니다. '안내문 및 신청서'처럼 둘 다 있으면 서류로 봅니다. 엑셀·이미지처럼 채울 수 없는 형식도 참고 자료로 둡니다.
- ‘열어 볼 서류’에는 서류만 나오고, 참고 자료는 ‘참고 자료 N개 — 신청서가 아니에요’ 아래에 내려받기로만 따로 둡니다.
- 채우기 전의 빈 원본은 미리 보여 주지 않고 작성된 서류만 보여 줍니다. 상담 등으로 정보가 이미 있으면 서류를 여는 즉시 채워 보여 줍니다. 자동 작성이 안 되는 서류만 원본을 보여 줍니다.
- 운영 DB 첨부 5,735개 기준: 서류 1,578개, 참고 자료 4,157개.

## AI 상담에서 서류 정보 받기

추천 결과를 보여 준 뒤 AI가 ‘신청서를 미리 채워 드릴까요?’라고 묻고, 원하면 이름 → 생년월일 → 연락처 → 주소를 차례로 받습니다. 받은 값은 형식을 정리해(생년월일 날짜 확인, 전화번호 하이픈, 주소 띄어쓰기) 서류 입력칸에 미리 넣습니다. 주민등록번호·계좌번호는 묻지 않고, 말해도 기록하지 않습니다.

## 쉬운 설명 자동 생성

미리 만든 AI 설명(`data/ai_cache`, 표본 50건)이 없는 서비스는 ‘쉬운 설명’ 탭을 열 때 `llm.make_easy`로 만들고(원문 숫자 검사 포함), 서버 메모리에 7일 보관해 다른 사람은 바로 봅니다. 키가 없거나 실패하면 공식 안내 원문을 보여 줍니다.

## 필요한 서류 자동 안내와 목록 나누기

- 공식 안내에 서류 목록이 없으면 ‘함께 준비할 서류와 떼는 곳’에서 AI가 자동으로(버튼 없이) 안내문을 읽고 필요한 서류·떼는 곳·온라인 바로가기·신청 순서·혼자 어려울 때 방법을 보여 줍니다. 안내문에 있는 서류는 ‘안내문에 있음’, 보통 필요한 서류는 ‘보통 필요 · 확인 필요’로 표시합니다. AI 실패 시 기본 서류를 보여 줍니다. 결과는 서버 메모리에 7일 공유합니다.
- AI가 쉽게 풀어 쓴 곳(쉬운 설명, 서류 안내) 바로 아래에 ‘원문 보기 (복지로 공식 안내)’를 둡니다.
- 복지 목록(상담 결과·전체 서비스)은 ‘📝 신청서 바로 작성 가능’과 ‘📄 신청서 파일 없음(받는 방법 안내)’ 탭으로 나누고 카드에 배지를 붙입니다. 운영 DB 기준 1,304개 / 3,995개.

## 실제 작성 결과 정밀 검토로 고친 것 (아동수당 서식모음 등)

- ‘입력한 내용으로 서류 채우기’ 버튼을 끄지 않는다(입력 직후 바로 누르면 꺼진 버튼의 클릭이 무시되던 문제). 정보 없이 누르면 안내만 띄운다.
- 서류를 열면 바로 서류를 보여 주고 ‘아직 내 정보가 들어가지 않은 서류’라고 표시한다.
- PDF 채운 글자는 서식과 같은 검은색. 큰 테두리 상자는 줄 단위로 구역을 판단(‘담당 공무원 확인’ 문장 때문에 신청인 날짜·서명이 빠지던 문제).
- 구역 판단: ‘본인(대리신청인 포함)’·‘신청인(보호자 또는 대리인)’=신청인, ‘아동의 인적사항’·‘수급아동’·‘변경 전 보호자’·‘연고자’·‘비상연락’=다른 사람, ‘단체/시설/기관 정보’=기관, ‘대표자 정보’=신청인. 짧은 구역 머리에만 적용(긴 신청 문장 속 단어 제외). ‘요청합니다·제출합니다’ 문장도 신청인 문장.
- PDF: 같은 쪽에 신청인·보호자 구역이 따로 있으면 보호자는 다른 사람. 괄호 안내 글자(‘(전화: )’)는 다른 칸으로 옮겨 쓰지 않음. 아래 칸은 좌우 폭이 라벨 칸과 같을 때만 사용. 칸 위쪽 라벨만 있으면 같은 칸 라벨 뒤 또는 아래에 기입. 서명란 ‘보호자 :’ 지원.
- 남은 한계: 글자 사이가 넓게 띄어진 PDF 라벨(‘주     소’)은 인식 못 함, ‘(휴대전화)’처럼 괄호 안 좁은 자리는 비워 둠, PDF 덧쓰기 글꼴은 서식에 박힌 글꼴과 다를 수 있음(HWP·HWPX는 서식 글꼴 사용).

## 첨부파일 전수 내용 검증 (`data/attachment_kinds.json`)

이름만으로 서류/참고 자료를 나누면 틀린다(예: ‘대통령과학장학금 홈페이지 신청서 작성 매뉴얼’). 운영 DB 첨부 5,358개를 모두 내려받아 내용으로 판정했다.

- 이름 기준 분류 대비 내용 검증: 이름=서류·내용=신청서 없음 348개, 이름=참고·내용=신청서 있음 622개가 어긋났다.
- 판정(`document_workspace.decide_kind`): 신청서 칸이 있으면 서류. 단 이름이 조례·지침·안내·계획이고 두꺼우면(PDF 10쪽 초과, 한글 150KB 초과) 참고 자료. 이름이 신청서·서식 묶음이면 크기와 무관하게 서류. 칸을 못 찾았으면 신청서·동의서·서약서·위임서·양식 등 신청인이 쓰는 이름일 때만 서류. ‘작성 매뉴얼·작성 방법·가이드’는 참고 자료.
- 결과: 서류 1,378개, 참고 자료 3,980개. 화면은 이 표를 먼저 쓰고, 표에 없는 새 첨부는 이름 규칙으로 판단한다.
- 갱신: `python scripts/build_attachment_kinds.py [--cache 폴더]` (약 6분, 첨부를 내려받아 판정). 예약 갱신에 붙이면 새 첨부도 내용으로 판정된다.

## AI 응답 속도와 길이

- 쉬운 설명(즉석 생성)은 `prompts/easy_short.txt` 짧은 프롬프트(누가·무엇을 한 문장, 조건·할 일 최대 3개)와 `reasoning_effort=none`으로 약 2.5초(이전 6.6초+재시도). 숫자 검사는 결과만 보여 주고 빠진 숫자는 ‘원문 보기’로 안내.
- 서류 안내는 단계 2~3개·서류 3~5개로 줄이고 `none`(약 5초, 이전 약 10초). 상담·추천 고르기는 `low`(한 턴 약 2초).
- 신청 안내를 열 때 쉬운 설명과 서류 안내를 동시에 만들어 처음 열기 약 7초(이전 차례로 약 17초). 결과는 서버 메모리에 7일 공유.
- 미리 만든 긴 설명(표본 50건)도 조건·할 일은 3개까지만 보이고 나머지는 ‘자세히 보기’.
- 모델이 reasoning_effort를 지원하지 않으면 옵션 없이 다시 요청.
- 상담: 같은 질문 반복 금지, 지역·나이·필요한 도움을 알면 바로 결과.

## 주소 확인(도로명주소 검색 API)

- 순서: 규칙 띄어쓰기 정리 → AI 검수(입력에 없는 숫자·시·도를 만들면 버림) → `JUSO_API_KEY`로 도로명주소 검색. 사용자가 ‘주소 확인하기’를 누를 때만 주소 한 줄을 보낸다.
- 검색 결과 중 입력한 도로명·건물번호가 **정확히 같은** 주소만 ‘확인한 주소’로 보여 준다. 비슷한 주소만 나오면 ‘똑같은 주소는 없어요’와 함께 고를 수 있게만 두고, 시·구만 적으면 ‘덜 적혔어요’로 안내한다. 같은 주소가 여러 번 오면 하나로 합친다.
- AI가 고친 검색어로 못 찾으면 규칙으로만 정리한 검색어로 한 번 더 찾는다(예: ‘세종대로 209’).
- ‘세종대로’, ‘대구로’, ‘부산진구’, ‘서울시립대로’처럼 지역 이름으로 시작하는 도로·구 이름을 시·도로 바꾸지 않는다.
- 지번(‘교촌리 123번지’)은 도로명주소로 바꿔 제안한다.
- 검증(2026-11-20): 실제 주소 28종 확인, 확인한 주소로 신청서 60개를 채워 결과 파일에서 주소 글자 확인 60/60, 브라우저에서 주소 확인→바꾸기→서류 채우기→저장 파일 확인(PDF·HWP·HWPX 각 1개).
- 팝업 API 승인키는 이 기능에 쓸 수 없다(검색 API 승인키가 따로 필요).
- **해외 서버 대응(2026-11-22)**: Streamlit Community Cloud(미국) 서버에서는 도로명주소 API 연결이 시간 초과로 막힌다(운영 로그 `[juso] URLError: <urlopen error timed out>`, 국내·일본 서버에서는 정상). 서버 검색이 연결 문제로 실패하면 사용자 브라우저가 같은 API를 직접 불러(도로명주소 API는 CORS `*` 허용) 응답만 앱으로 돌려주고, 서버와 똑같은 규칙(정확 일치·비슷한 주소·상세주소 붙이기)으로 처리한다. 한 번 연결에 실패하면 10분 동안은 서버 시도를 건너뛰어 기다리지 않게 한다. 브라우저에서도 실패하면 ‘도로명주소 검색을 쓰지 못해’ 안내를 그대로 보여 준다.
- 이 방식에서는 검색 API 승인키가 사용자 브라우저 요청에 실린다. 이 키로는 주소 검색만 할 수 있고 노출되면 juso.go.kr에서 재발급하면 된다. 다른 키(LLM·MongoDB)는 이 경로로 내보내지 않는다.
