# 프로젝트 계획서 (안)

| 항목 | 내용 |
| --- | --- |
| 프로젝트명 | 복지문턱 (가제) |
| 프로젝트 설명 및 목표 | 복지서비스마다 신청 문턱 점수를 이유와 함께 보여주고, 안내문을 쉬운 설명 카드로 바꿔 준다 |
| 주제 | 공공 복지서비스 데이터로 신청 절차 복잡도 측정, 언어 모델로 안내문 쉽게 바꾸기 |
| 주제 선택 이유 | 조건·기관·서류가 긴 글에 섞여 있어 자격이 있어도 신청을 포기하기 쉽다 |
| 데이터 및 출처 | 공공데이터포털 복지서비스 API (중앙부처, 지자체). 11/10 샘플 50건 확인 |
| 수집·전처리 방법 | API로 전체 서비스 수집·저장, 온라인·방문 여부 정리. 서류는 신청방법 글에 있는 것만 쓰고, 없으면 "서류 정보 없음" |
| 분석 방법 및 지표 | 항목별 점수를 더해 0~100점 문턱 점수 계산. 조건 수·서류 목록은 언어 모델로 추출 |
| 검증 방법 | 50~100건 정답표와 비교, 단순 규칙 대비 정확도 비교, 쉬운 설명의 숫자 누락 자동 대조 |
| UI 및 기능 | 문턱 점수 화면, 쉬운 설명 카드, 신청서·위임장 채우기(설계만) |
| 사용 기술 | Python, 언어 모델 API 1개, Streamlit |
| 팀원 및 역할 | 3명. 데이터 / AI / 검증 / 화면·발표 네 가지 일을 나눠 맡음 (담당자 미정) |
| 개발 일정 | 11/17까지 문턱 점수·쉬운 설명 화면 시연, 신청 준비는 설계만. 12/1 24:00 최종 제출 |
| 산출물 구성 | 코드, README, 계획서, 발표자료 PPT, YouTube 시연 영상, (선택) Streamlit 배포 URL |

## 문턱 점수 항목 (안)

| 항목 | 점수 |
| --- | --- |
| 온라인으로 신청할 수 없음 | +3 |
| 꼭 방문해야 함 | +2 |
| 거치는 기관(신청·조사·결정) | 기관 하나마다 +1 |
| 받을 조건 | 조건 하나마다 +1 |
| 내야 하는 서류 | 서류 하나마다 +0.5 (글에 없으면 비워 둠) |
| 안내문 난이도 | 0~3 |

가중치는 미국의 복지 신청 부담 평가 기준을 참고해 팀이 확정한다.
